# Gap-Hunting Protocol

## Objective

Find mathematical and controlled-chain gaps that a green build cannot detect.

## Scan order

1. Crown claim cards.
2. Required standing paths.
3. Composition tests.
4. Flow tests.
5. Correspondence maps inside TTL → ggen → Lean → Lake → audit.
6. Countermodel obligations.
7. Mutation survival.
8. Metamorphic relations.
9. Exact theorem inventory.
10. Policy coverage.

## Gap classes

- `MISSING_NODE`: required carrier/theorem does not exist.
- `MISSING_EDGE`: neighboring carriers exist but no preservation/composition theorem connects them.
- `VACUOUS_WITNESS`: theorem only fires under uninhabited or artificial assumptions.
- `FORGEABLE_AUTHORITY`: caller can construct a standing/receipt/admission value without witness.
- `NOMINAL_CORRESPONDENCE`: similar names/fields but no proved map.
- `FINITE_TO_GENERAL_OVERCLAIM`: bounded experiment presented as theorem.
- `SNAPSHOT_TO_SEMANTICS_OVERCLAIM`: golden equality presented as semantic law.
- `BENCHMARK_TO_COMPLEXITY_OVERCLAIM`: timings presented as formal bound.
- `SYNTAX_TO_CONCURRENCY_OVERCLAIM`: `.par` or width metric presented as commutation.
- `EMPTY_AUDIT`: zero required checks passes.
- `ORPHAN_THEOREM`: theorem exists but is not on a crown path.
- `ORPHAN_TEST`: test passes but does not discharge a declared claim/witness.
- `UNTYPED_REFUSAL`: generic error loses causal classification.
- `CLAIM_CEILING_BREACH`: claim metadata exceeds theorem/evidence standing.

## Output

Every gap report must name:

- gap class;
- exact node or edge;
- exact declaration/file;
- same-object falsifier;
- atlas test IDs capable of exposing it;
- minimum witness to close it;
- claim ceiling while open.
